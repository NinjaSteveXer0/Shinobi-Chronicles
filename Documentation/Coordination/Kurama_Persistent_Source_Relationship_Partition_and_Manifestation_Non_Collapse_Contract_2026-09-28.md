**Date:** 2026-09-28

## 1. Purpose

Combat has entered Kurama-family RESET-v2 Batch 4.

Current Shinobi Chronicles authority now contains several exact Kurama-family representations whose names, host histories, partition states and lifecycles overlap.

This contract prevents those representations from collapsing into duplicate beasts, duplicate source packages, false ownership, false partnership, or stacked half/whole mechanics.

It does **not** author:
- new Combat Skills;
- new Enhancements;
- relationship thresholds;
- generic Jinchūriki acquisition/implantation;
- Breakout Fūinjutsu thresholds;
- generic berserk/loss-of-control rolls;
- new PL;
- new Registry identities.

Canonical shorthand:

> **One persistent Kurama source can have different partition, relationship, host-history and lifecycle representations without becoming several unrelated Kuramas.**

## 2. Core semantic axes

Kurama-family state must be read across separate axes.

### 2.1 Persistent source identity

Nine-Tails, Kurama, Yin Kurama, Yang Kurama, Menma-specific Kurama representations, Complete Kurama, Breakout Kurama and Reborn Kurama do not automatically imply unrelated persistent beasts.

Where current authority links them, they are representations/lifecycle states of the same underlying Kurama source/history.

Exact representation != new persistent source by default.

### 2.2 Partition / body state

Partition/body state is separate from relationship state.

Current closed meanings:

- **Yang** = Yang Kurama partition;
- **Yin** = Yin Kurama partition;
- **Complete Kurama** = reunited whole after partition resolution.

A partition can develop a different relationship with its host without changing which partition it is.

### 2.3 Relationship state

Relationship state is separate from partition/body state.

Current closed relationship distinction:

**Nine-Tails-state**
- pre-genuine-partnership;
- may be hostile;
- may be coercive;
- may be manipulative;
- may be transactional;
- may be cordial;
- may lend/grant chakra;
- may permit cloak access;
- may act from self-interest.

**Kurama-state**
- genuine voluntary partnership/cooperation;
- host and Kurama knowingly choose to work together.

Therefore:

> friendly dialogue != partnership

> cordiality != partnership

> chakra access != partnership

> cloak access != partnership

> one voluntary loan != partnership

> control != cooperation

> power taken != power freely given

### 2.4 Host/history-specific representation

An exact representation may encode the history of one host/source relationship in addition to partition state.

A host-specific representation must not be mechanically collapsed into a generic partition representation merely because the same partition underlies both.

### 2.5 Lifecycle / manifestation state

Hosted, forced-manifested, reunited and reborn states are separate from simple relationship-state naming.

A Forced Manifestation is not ordinary Summon ownership.

A reborn Hosted Entity is not merely a renamed earlier host package.

## 4. Partition reservation and exclusivity

### 4.1 One exact partition cannot occupy incompatible hosts simultaneously

A single exact Kurama partition cannot be simultaneously hosted/deployed through incompatible current representations merely because multiple collectible cards/assets exist.

Example:

If Naruto currently hosts the Yang partition, that same exact Yang source cannot simultaneously be established as another Character's hosted Yang source unless a legitimate transfer/extraction/resealing occurrence moved it.

### 4.2 Menma-specific Yin representation reserves the same underlying Yin source

Where Menma's current history uses the Yin half:

- `menma_nine_tails`;
- `menma_kurama`;
- generic `yin_kurama`

must not be treated as three independent Yin beasts.

Any exact current-state use must preserve one underlying Yin partition reservation.

### 4.3 Complete Kurama resolves the split state

Where `kurama_complete` is the current legitimate body state, the same Chronicle cannot also mechanically treat separate Yin and Yang halves as independently available current sources unless exact causal history has since split the whole again.

Historical prior-state display does not create simultaneous mechanical availability.

### 4.4 Reborn lifecycle is chronological, not duplication

Kurama's reborn state must not create an additional simultaneous Kurama beside an earlier living Kurama in the same linear history.

Any alternate-world/multi-history exception requires explicit authority; do not infer one from collectible-card coexistence.

- lent chakra;

Obtainability, ownership, transfer and host-establishment require exact Acquisition/Character Systems authority.

A visual/card asset existing in the repository does not close that system.

## 7. Forced Manifestation non-collapse

A Forced Manifestation uses the same persistent source that was previously hosted/sealed; it does not create a second source by emerging.

Unless an exact later owner contract states otherwise:

- the host cannot simultaneously receive the full hosted source package **and** a second full Breakout source package from the same exact Kurama source as if two Kuramas exist;
- emergence must be treated as a source-state transition/manifestation occurrence;
- any host access remaining during/after emergence must be authored explicitly;
- the Forced Manifestation's Battle PL is its own exact Entity/runtime state and does not become bonus host PL.

## 8. Anti-double-count contract

### 8.1 Entity PL never transfers wholesale

Kurama-family Entity Base PL does not become host Base/Effective PL merely because the source is hosted, partnered or manifested.

Only exact authorised host modifiers/actions/states apply.

### 8.2 Dedicated representation package beats additive source stacking

A dedicated Jinchūriki/hosted/embodied representation must not receive a second full source package merely because the source is also represented elsewhere.

### 8.3 Relationship upgrade replaces the current relationship package

For the same host + same exact partition:

`Nine-Tails-state package -> Kurama-state package`

is a state transition.

Do not run both full relationship packages simultaneously unless one exact Combat contract deliberately preserves a narrowly scoped inherited action/effect.

### 8.4 Complete replaces half stacking

`kurama_complete` uses one complete package.

Do not add:
- Yang package;
- Yin package;
- Complete package

together by default.

### 8.5 Menma-specific representation does not stack generic Yin automatically

`menma_kurama` may be underlain by Yin Kurama, but this does not mean:

`menma_kurama package + yin_kurama package`

unless an exact contract authorises a specific shared/common capability.

### 8.6 Family-common capability is separate from signature package

A legitimate family/common Kurama/Bijū capability may be shared across representations where Combat explicitly authors that common layer.

Shared capability does not justify stacking entire representation packages.
