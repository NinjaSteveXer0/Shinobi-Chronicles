# 2. Hard image lock and generation conservation

## 2.1 Image lock

No image generation anywhere in the Project unless Stephen uses the exact phrase:

`generate now`

`make it`, `go ahead`, `do this one`, `looks good`, or similar wording is NOT equivalent.

## 2.2 Two-failure maximum

Maximum **TWO failed generation attempts per requested asset**.

After the second hard failure, STOP GENERATING and return to reference review, canon research, identity verification, prompt diagnosis, composition planning, or hard-geometry rewrite.

A failed attempt must teach the next prompt something concrete.

## 2.3 Acceptance rule

> **A beautiful wrong asset is still a failed asset.**

Generation success is not production approval. Post-generation QA must check every hard constraint before calling an asset acceptable.

- exact **0.70:1 portrait ratio**;
- premium cinematic fantasy-anime / premium++ modern game-card finish;

# 5. Reference, age, affiliation and surgical-edit doctrine

## 5.1 Reference authority

If Stephen supplies an image and identifies features it controls, that image is primary visual authority for those features. Do not overwrite it with generic clan/fandom assumptions.

## 5.2 Genin age

Shinobi Chronicles may create Genin representations for characters from any era. A roughly **10–13-year-old Genin must actually read as a child / early adolescent**: youthful facial proportions, smaller jaw/chin, age-appropriate stature/build, no adult musculature or veteran adult face with `GENIN` underneath.

## 5.3 Location != affiliation

> **Konoha is a location, not a watermark.**

Do not automatically add Leaf headbands, banners, Hokage Rock, Leaf-marked buildings, clan/faction symbols or in-world affiliation marks merely because a character is Konoha-associated or the scene occurs there. Decorative card iconography is separate from world evidence.

## 5.4 Surgical edit

When Stephen requests a surgical edit:

- change only the named item(s);
- preserve subject identity, pose, geometry, spacing, frame, typography, colour, lighting, texture and unrelated content;
- when removing baked content, reconstruct the background beneath it;
- do not “improve” adjacent areas.

M. top-left icon where required;  
N. border/frame where required;  
O. exact allowed text;  
P. forbidden content;  
Q. set/trilogy differentiation;  
R. likely generator failure modes.

If the generator tends to approximate a required fact, **turn it into geometry**:

1. exact count;
2. simultaneous visibility;
3. spatial assignment;
4. explicit negative definition of what does not count;
5. final failure condition if the count is wrong.

This applies to tails, tomoe, wings, horns, clones, floating weapons, Truth-Seeking Balls, Summons, limbs, eyes and all other count-sensitive features.

# 7. Series / trilogy differentiation doctrine — DESIGN CLOSED

> **Same collection != same composition with more effects.**

Before producing a set, design the differentiation matrix first. Sibling cards must materially differ in:

- body silhouette / pose;
- facial expression;
- camera/composition;
- environment/background;
- lighting direction;
- energy geometry/action;
- border architecture;
- top-left icon;
- dominant visual rhythm.

Progression should change the **visual verb**, not merely increase glow.

The Rin/Isobu production run is the concrete lesson: vague `Three-Tails chakra` repeatedly produced two visible tails and repeated body language; exact count + visibility + assigned tail regions + exclusions solved the anatomy problem, and explicit stage composition solved repetition.

# 8. Tailed Beast visual doctrine — NEW DURABLE AUTHORITY

A Tailed Beast's **numbered title** and **true-name representation** are two visual states of the same underlying being.

## Numbered Beast

Examples: `ONE TAIL`, `THREE TAILS`, `SIX TAILS`, `NINE TAILS`.

This represents how the world encounters the beast while wild/uncooperative: hostile, territorial, violent, destructive, alienated, catastrophic.

# 14. Recurring generation failures and permanent corrections

## Wrong character / substitution

Failure: generator produced a different character when requested identity was unclear.  
Rule: silently verify **which exact character am I generating?** If uncertain, stop. Never substitute.

## Wrong age / adult-on-child body

Failure: historical Genin variants looked adult, including “adult head on kid body.”  
Rule: encode age through face proportions, jaw/chin, stature and build — not just title text.

## Wrong counted anatomy

Failure: Rin/Three-Tails prompts named the lore but repeatedly showed only two tails.  
Rule: exact count + simultaneous visibility + separate regions + base-to-tip contour + explicit non-tail exclusions + fail if count differs.

## Repeated trilogy composition

Failure: Manifestation repeated Resonance pose/body language/background.  
Rule: plan differentiation matrix before generation; change visual verb, silhouette, expression, camera, environment, lighting, energy geometry, border and icon.

## Contact sheets / composites

Failure: batch requests became multi-character sheets.  
Rule: one image = one asset. Five requested portraits means five independent outputs.

## Card/portrait contamination

Failure: card frame/icon/nameplate entered portrait work or portraits were treated as card crops.  
Rule: asset class is a hard preflight constraint; portraits are separate frameless masters.

## Filename/archetype identity drift

Failure: enemy portrait generation inferred generic people from filenames.  
Rule: exact approved representation source -> visual anchors -> purpose-built portrait -> mapping -> QC.

## Canon override vs fanfic drift

Two opposite failures are prohibited:

- canon research overwriting an intentional SC divergence;
- fanfiction drifting so far that the underlying character stops being recognisable.

Rule: canon identity anchor -> explicit SC divergence -> resulting visual logic.

## Failure to consume GitHub before generation

Concrete 2026-09-12 failure: One-Tailed Cloak Menma was generated red despite #124 explicitly locking black chakra.  
Rule: before canon/SC-variant generation, inspect current relevant GitHub authority, not merely memory or the user's short generation line.
