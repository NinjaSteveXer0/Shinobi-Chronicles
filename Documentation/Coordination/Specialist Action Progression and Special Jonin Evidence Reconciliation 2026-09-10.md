# Shinobi Chronicles — Specialist Action Progression and Special Jōnin Evidence Reconciliation

**Date:** 2026-09-10  
**Owner:** CE / Codex / Coordination  
**Source issue:** GitHub #60  
**Status:** **BINDING ALPHA RECONCILIATION — #59 DOES NOT SUPERSEDE THE CLOSED SPECIAL JŌNIN EVIDENCE MODEL**

## Decision

GitHub #59 and its Writing clarification do **not** supersede the closed Special Jōnin contextual-development architecture.

For Alpha:

1. **Special Jōnin specialization development remains exact provenance-bearing qualification evidence, not a numeric Specialisation EXP currency or ledger.**
2. A committed specialist action may create that evidence **at action/occurrence time** when the factual contribution satisfies the existing producer-projection contract.
3. The evidence may remain hidden from ordinary player presentation. Hidden presentation does not change its ontology into XP.
4. Existing evaluator, qualification, Recognition and Rank semantics remain unchanged.
5. #59 may request **other domain-owned Skill/proficiency development** only where that domain already has explicit authority for that exact learning-by-doing progression. #59 itself does not create a new generic Skill EXP, proficiency EXP or Specialisation EXP system.

Canonical shorthand:

> **hidden progress ≠ hidden XP ledger**

> **committed specialist action → authorised domain consequence(s), not one universal specialization currency**

## Interpretation of #59 wording

Writing's phrase **"Skill / Specialisation / proficiency EXP"** is an authorial intent statement about learning-by-doing, not authority to create a universal progression ledger.

It must be split by owning domain.

### A. Special Jōnin specialization development

When a committed action genuinely demonstrates one exact current Alpha Special Jōnin competency, Progression may project the existing qualification evidence immediately from that occurrence.

Examples, only when the facts genuinely satisfy the existing path:

- meaningful interrogation → `intelligence.interrogator` evidence;
- stabilisation under field conditions → `medical_operations.field_medic` evidence;
- trail analysis / intercept work → `reconnaissance.tracker_nin` evidence;
- seal analysis / execution → `fuinjutsu_operations.sealing_specialist` evidence.

Broad verbs are **not** qualification IDs.

`Contain`, `Protect`, `Medical`, `Track`, `Interrogate`, `Seal`, etc. must resolve to an exact authorised path and exact demonstrated tags or produce **no Special Jōnin evidence**.

In particular, pure generic protection/guard/bodyguard work still has no universal Alpha Special Jōnin fallback. It may project only when the actual work independently satisfies an existing path such as extraction or conflict mediation.

### B. Other Skill / proficiency development

A committed specialist action may also produce development owned by another existing system **only if that system already authorises the exact progression consequence**.

Examples might include an existing Skill, discipline, technique or proficiency system whose own contract explicitly supports EXP/development from legitimate use.

This document does **not** assert that every such system currently exists, nor does it authorise World, Writing or Coding to invent one from #59 wording.

If no existing domain authority supports the proposed EXP/development consequence:

- preserve the factual occurrence;
- preserve Knowledge/history/access/evidence consequences where authorised;
- project Special Jōnin evidence only if the existing exact path qualifies;
- do **not** fabricate a new XP ledger.

Canonical rule:

> **authorial learning-by-doing intent ≠ authority to mint a new progression currency**

## Action-time progression versus debrief rewards

#59 correctly distinguishes two layers.

### Layer 1 — occurrence-time development

A legitimate committed specialist action may create its authorised participant-specific development consequence at the moment the factual action commits.

This is not a mission-completion reward.

For Special Jōnin, that means qualification evidence projection under #20/#23.

### Layer 2 — mission / Arc debrief reward package

The later debrief may independently grant or acknowledge authorised material/economic/access/opportunity/performance rewards from the completed Chronicle.

The debrief must not re-award the same occurrence-time development merely because it summarises it.

A debrief may acknowledge that specialist work occurred without minting duplicate evidence or XP.

Preserve:

> **occurrence-time development ≠ debrief reward pool**

> **debrief acknowledgement ≠ second progression commit**

## Multi-channel consequence rule

One committed occurrence may legitimately produce several consequences when each is separately authorised, for example:

- Chronicle history;
- observer-bounded Knowledge;
- relationship / reputation evidence;
- exact Special Jōnin qualification evidence;
- an existing domain-owned Skill/proficiency consequence;
- future access/opportunity changes;
- material entitlement.

These channels may share one factual source occurrence while retaining their own domain authority.

They must not be collapsed into one generic reward score.

## Participant attribution and anti-farming

The source unit is the committed factual occurrence, not the visible option or UI interaction.

Required:

- exact participant attribution;
- exact `sourceOccurrenceId` / causal provenance;
- no whole-team award from mere presence;
- no award from option visibility alone;
- no duplicate consequence on retry/save/load/UI replay;
- no counterfeit independent-source breadth from child actions under one causal task;
- repeated legitimate development requires genuinely distinct qualifying occurrences.

Preserve:

**choice visible ≠ action committed**  
**action committed ≠ every development channel automatically**  
**participant presence ≠ participant contribution**  
**same occurrence ≠ repeated reward**

## World / Rewards authoring guidance

World may finalise #59 under this interpretation.

For specialist actions, World should author or preserve:

- the exact factual action/result;
- exact participant;
- source occurrence / causal provenance;
- exact qualification relevance when already authoritative;
- other existing domain-development intent only where that domain authority exists;
- separate debrief reward eligibility/provenance.

World must not author generic rewards such as:

- `+5 Medical Specialisation EXP`;
- `+10 Interrogation EXP`;
- `+Protect EXP`;
- family-level hidden Special Jōnin XP.

Instead, the committed specialist work becomes the factual source from which the owning progression systems project legitimate consequences.
