This document consumes Writing's closed Story→World→Story bridge and makes it executable as World authoring doctrine without creating a second event system.

`committed Story fact`
→ `exact World eligibility`

- later relevance != retroactive completion;
- current custody != permanent custody;
- Knowledge != Access != Competence != Power != Mastery;
- Story callback consumes actual committed history, not `sideQuestComplete=true` shorthand.

## 4. General Main-Story off-shoot authoring rule

A Main Story unresolved fact may generate an optional World off-shoot only when World can name the exact committed prerequisite that makes the off-shoot causally legitimate.

A generic authoring signal such as `WORLD_OFFSHOOT_ELIGIBLE` may be retained in Writing notes, but it is not a new runtime eligibility layer.

World must still author:

1. source-history facts;
2. candidate family / chain identity;
3. exact eligibility predicates;
4. Knowledge / discovery boundary;
5. actionability boundary;
6. location / participant / object context;
7. legal responses;
8. factual outcome envelope;
9. non-action / delay treatment;
10. expiry / suppression / transformation rules;
11. reward / consequence envelope;
12. exact facts later Story may query.

Not every loose end deserves an off-shoot. A valid off-shoot should create at least one meaningful new Character-specific opportunity, consequential Knowledge/provenance, relationship/contact, changed custody/state, future eligibility, distinctive location interaction, or later Story input.

## 9. First-opportunity response families

`world_evt_a2m3_sealed_wall_private_reckoning_01` supports these factual response classes.

### A. Leave it untouched

Intent:

Preserve the exact state and do nothing further for now.

Result:

- custody remains Menma's;
- no new observer learns the truth;
- no Knowledge is fabricated;
- no reward is lost;
- the chain remains dormant/eligible for later causal triggers.

This is **not failure** and carries no morality penalty.

### B. Perform a bounded non-invasive re-observation

Intent:

Review only the state/architecture Menma already knows how to monitor from the A2M3 resolution, without opening, impersonating an owner or altering authentication.

Permitted result envelope:

- commit a new time-stamped observation of what Menma can legitimately perceive;
- confirm only whether an authored observable state appears unchanged / changed / indeterminate relative to his previous observation;
- if a change is authored, record the observable change without magically identifying its cause.

Forbidden result:

- auto-identifying the chakra owner;
- opening the chamber;
- deriving the null-bridge duration from nowhere;
- creating a new Fūinjutsu/Kinjutsu Skill;
- implying False Identity compatibility.

### C. Prepare a provenance / records question

Intent:

Use the architecture already observed to formulate a documentary question without disclosing the physical chamber.

Result:

- may create an **archival-lead eligibility fact**;
- may later make a documentary opportunity at an already legitimate archive host eligible;
- does not guarantee that a useful record exists;
- does not reveal a hidden location or owner.

Stable follow-up candidate ID:

`world_evt_a2m3_sealed_wall_archival_trace_01`

Default preferred host when separately discovered/actionable:

`KON-O17` Academy Archive Annex.

### D. Disclose a bounded description to a trusted participant

Intent:

Tell a legitimately selected trusted Character only what Menma chooses to disclose.

Eligibility:

Requires an actual relationship/contact and a context in which that participant can be approached.

Result:

- commits exact observer Knowledge gained by that participant;
- may change relationship/shared history;
- may create future specialist-contact eligibility;
- may create future exposure/risk only if later causal events support it.

No participant automatically gains the complete chamber truth.

Stable follow-up family:

`world_family_a2m3_sealed_wall_trusted_consultation_v1`.

### E. Seek a safer custody arrangement

Intent:

Move or share custody without exposing the object publicly.

This action is shown only if a legitimate recipient/location/custody route already exists.

World must never invent a generic `secure vault` merely because the player selected this intent.

Possible outcomes:

- sole custody transferred;
- shared custody established;
- proposed transfer refused;
- transfer aborted;
- custody remains Menma's.

Each result commits the factual current holder(s) and observer Knowledge.

### F. Deliberately disclose / surrender the chamber state

This is not a default recommended action but may become legal when an actual authority/contact is available.

If chosen:

- current custody changes factually;
- the private chain transforms/suppresses;
- later Story must consume the new custody state;
- disclosure does not grant that institution instant understanding or owner identification.

## 12. Expiry, delay, suppression and transformation

### No arbitrary timer

There is no authored fixed expiry merely because the player continues Main Story.

While custody remains stable and no factual external pressure exists, the private chain may remain dormant indefinitely.

### Delay / non-action

Delay is a legitimate result.

Do not:

- punish with hidden morality;
- remove unrelated rewards;
- invent chamber deterioration;
- make ROOT automatically seize it;
- retroactively claim Menma investigated it.

### Suppression

Suppress a node when its premise is no longer factually true.

Example:

if custody leaves Menma, `private_reckoning_01` suppresses and an appropriate custody/recovery/Story branch may become eligible.

### Transformation

A chain may transform rather than simply complete:

- private mystery -> archival investigation;
- private custody -> trusted shared custody;
- secret custody -> contested custody;
- unknown owner -> known owner but still inaccessible;
- intact chamber -> altered/damaged evidence state;
- optional World thread -> later Writing-authored Story pressure.

Transformation preserves prior history; it does not reroll the original occurrence.

## 14. Loss / failure / non-action doctrine

A later failed investigation does not erase legitimate facts already learned or actions already completed.

Examples:

- if Menma identifies a real archive provenance clue and later loses custody, that Knowledge remains;
- if a consultant is contacted and later refuses further help, the relationship/history still happened;
- if an archive search produces no answer, the search itself may establish that a record is absent from the searched scope without proving that no record exists anywhere;
- if Menma chooses not to investigate, no hidden `failure` flag is created merely for leaving it alone.

**Battle loss != mission failure. Mission failure != zero Chronicle value.**

This chain does not require Battle at all unless a later authored custody-pressure occurrence legitimately creates one.
