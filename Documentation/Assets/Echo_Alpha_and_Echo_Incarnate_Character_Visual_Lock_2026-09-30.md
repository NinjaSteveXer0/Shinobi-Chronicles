## 1. Route ownership

The Echo progression belongs specifically to **Menma's route**.

The stable underlying Hosted Entity remains:

`arc1_menma_echo`

The existing host relationship remains:

`host_rel_menma_arc1_echo`

Do not generalise this Echo progression into a universal Origin reward. Other Origin characters may receive their own distinct route-specific side-quest developments, entities, companions, summons, transformations, equipment, relationships or other authored rewards, but they do not automatically receive Echo equivalents.

Canonical presentation rule:

> **Menma's Echo route is bespoke to Menma. Other Origins should receive different authored route identity rather than Echo copies.**

## 2. Persistent identity

Echo, Echo Alpha and Echo Incarnate are **not three different beings**.

They are representation / manifestation states of the same persistent causal Entity:

`arc1_menma_echo`

Preserve:

> **representation development ≠ new Entity identity**

> **greater manifestation stability ≠ Registry identity replacement**

## 3. Echo Alpha

Player-facing card classification:

**HOSTED ENTITY**  
**ECHO ALPHA**

Meaning:

**Echo Alpha is the Echo's first stable, self-authored external manifestation.**

"Alpha" does not mean rarity tier, generic level-up, clone, second Echo or new species. It marks the first form the Echo can deliberately maintain as an expression of itself rather than merely appearing as an unstable hosted manifestation.

Narrative direction:

- post-Arc-1 / later Menma-route Side Quest development;
- the Echo begins holding visible form for longer periods;
- it expresses clearer independent preference and intent;
- it learns to stabilise a chosen external appearance;
- it remains the same Hosted Entity attached to Menma;
- reciprocity with Menma is prerequisite historical context, not ownership/mastery.

Visual read of the approved Echo Alpha Battle Portrait:

- one dominant central coherent form;
- rear/secondary silhouettes read as resonance, residual positions or unstable echo-images of that same being;
- they are not separate creatures.

## 4. Echo Incarnate

Player-facing working classification:

**HOSTED ENTITY**  
**ECHO INCARNATE**

Echo Incarnate is a later Menma-route manifestation state in which the same Echo can maintain a substantially more complete, durable external body while remaining causally hosted / tethered to Menma.

The word "Incarnate" means the Echo can **hold a body**, not that it has automatically become a separate Summon or independent Registry person.

While `host_rel_menma_arc1_echo` remains active:

- Echo Incarnate remains **Entity → Hosted Entity**;
- external manifestation does not create an ordinary Summon lifecycle;
- manifestation does not automatically create an independent deployment slot;
- manifestation does not automatically create a second Battle turn;
- manifestation does not automatically create an independent Stat/PL ledger;
- greater autonomy does not equal ownership or mastery.

Combat / Progression must author any later capabilities explicitly.

## 5. Do not convert Echo Incarnate into a Summon merely to "free a Hosted Entity slot"

Current CE authority already permits one host to maintain more than one separately-authored Hosted Entity relationship.

Therefore there is no universal single Hosted Entity slot that must be freed.

Canonical rule:

> **one host ≠ one universal Hosted Entity slot**

Making Echo Incarnate a Summon solely to free a slot would collapse relationship semantics for inventory convenience and is rejected.

A Summon classification would require its own legitimate summoning relationship / contract / lifecycle authority. External visibility or temporary separation is not sufficient.

## 6. Future independent-existence boundary

If a later Story route establishes that the Echo can persist independently **without residing in, remaining tethered to, or requiring Menma as host**, then the relationship may legitimately change.

At that point the same persistent Echo could become:

**ENTITY / ECHO INCARNATE**

or another separately authorised standalone Entity presentation.

That transition would mean:

- same persistent Entity identity;
- Hosted relationship changed/ended;
- not automatically a Summon;
- Registry / CE / Progression / Combat follow-through required before implementation.

Preserve:

> **hosted → independent Entity is a relationship/classification change, not a new being**

> **independent Entity ≠ Summon automatically**

## 7. Side Quest direction

Preferred long-form Menma-route progression:

1. **Echo** — existing hosted presence / Arc-1 relationship.
2. **Echo Alpha** — first stable self-authored external manifestation.
3. **Echo Incarnate** — later durable external embodiment while still Hosted.
4. Optional future branch only if separately authored: permanent independent Entity state.

This progression should be earned through Menma-route Side Quests and relationship/history evidence rather than simply awarded from card ownership.

Exact quest writing, progression predicates, skills, battle actions, PL, acquisition and runtime implementation remain with their existing owners.

## 8. Other Origin characters

This document authorises **asymmetric route rewards**:

> **fairness does not require identical supernatural progression across Origins.**

Exact alternate Origin rewards are not authored here.
