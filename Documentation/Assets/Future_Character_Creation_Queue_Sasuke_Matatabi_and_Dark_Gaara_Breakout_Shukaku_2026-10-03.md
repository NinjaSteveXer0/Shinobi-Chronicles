# 1. Sasuke + Matatabi / Two-Tails Jinchūriki Series

## Locked concept

Create a future authored **Jinchūriki Part 2** series for **Sasuke + Matatabi / Two-Tails**.

This pairing is approved as a future Character Creation family.

It must use the current Part-2 created-Jinchūriki representation grammar:

> **RESONANCE -> MANIFESTATION -> AVATAR**

The series is the same Sasuke person across the three representations and the same persistent Matatabi/Two-Tails Beast source across the host relationship.

## Relationship / representation boundary

Matatabi and Two-Tails are the same persistent beast with different exact relationship/presentation states.

Future Sasuke visual authoring must preserve whichever exact source state is authorised by Progression/Story/Registry at each stage rather than inventing a separate Beast.

Do not assume:
- all three stages are cooperative Matatabi;
- all three stages are hostile Two-Tails;
- the relationship state changes automatically merely because the representation advances.

Exact stage-to-relationship mapping remains future owner work.

## Visual identity direction

The future series should visibly combine:
- Sasuke's exact authorised age/stage/representation;
- Matatabi/Two-Tails' canon-grounded blue-flame bakeneko identity;
- exactly two-tail source identity where the Beast is visibly manifested;
- Matatabi heterochromia and blue/black flame-body language where the Beast itself is shown;
- Sasuke-specific silhouette, costume and ocular/chakra identity only where the exact representation authority supports it.

Do **not** reduce the line to generic blue flames around Sasuke.

Each stage must materially evolve composition, silhouette, energy geometry and host/Beast integration under the Character Card series rules.

## Future asset expectation

When semantics close, Character Creation / Visuals should expect:
- one premium Character Card for **Sasuke Resonance**;
- one premium Character Card for **Sasuke Manifestation**;
- one premium Character Card for **Sasuke Avatar**;
- matching Battle/UI portrait(s) where implementation requires them.

Exact filenames, title hierarchy, Sasuke age/stage, costume, Sharingan state, relationship state and Battle Portrait necessity remain unresolved until live authority closes them.

# 2. Dark Gaara Coercive Seal Route

## Locked concept

Create a future **Dark Gaara** Jinchūriki Part-1 coercive route built around Gaara deliberately developing **Fūinjutsu** and manipulating his existing Shukaku seal **without One-Tail/Shukaku cooperation**.

This is conceptually analogous in ambition to Naruto's Stolen Chakra route but must remain **Gaara + Shukaku specific**.

Canonical shorthand:

> **Gaara improves Fūinjutsu -> experiments with / manipulates his seal -> forces greater One-Tail access without cooperation -> risks or causes Forced Manifestation.**

This is **not** the cooperative Shukaku route.

This is **not** a hidden morality score.

This is **not** permission to copy Dark Naruto's exact visual progression, colours, stage count, mechanics or Black Gold KCM structure.

Shukaku authority already preserves:

> each Jinchūriki's coercive/dark path must remain unique to that host + Bijū relationship.

## Existing compatible Shukaku foundation

Current One-Tail authority already supports a non-cooperative foundation:
- **Cracked Seal Conduit**;
- dangerous partial possession;
- **Possession Claw**;
- **Sand Maw Eruption**;
- **Malice Breakout**;
- seal strain / violent source pressure;
- uncooperative One-Tail remains mechanically valuable rather than a punishment version.

The Dark Gaara route should build from that identity, not overwrite it.

## Forced Manifestation endpoint / branch

Lock the future representation concept:

**FORCED MANIFESTATION**  
**BREAKOUT SHUKAKU**

`Breakout Shukaku` is the same persistent Entity:

`beast_shukaku`

in a host-specific **Forced Manifestation** state caused by Gaara's coercive seal route / loss-of-control or authored breakout condition.

It is:
- not a new Shukaku;
- not ordinary cooperative `shukaku`;
- not merely wild `one_tail` with a different label;
- not an ordinary Summon;
- not automatic permanent ownership of an external Shukaku body.

Exact occurrence, persistence, Battle deployment and post-breakout consequences remain future Story/Progression/Combat/Registry work.

## Visual direction for the future Dark Gaara family

When generated later, the visual language should be uniquely Gaara/Shukaku:

- cracked / rewritten seal geometry;
- Shukaku cursed-marking influence;
- sand pressure and unstable partial possession;
- increasingly visible One-Tail anatomy pushing through Gaara's controlled seal work;
- Fūinjutsu authorship should be visually legible as **Gaara manipulating the seal**, not Shukaku voluntarily blessing him;
- hostile sand/chakra breakout pressure rather than Kurama-style cloak imitation;
- preserve Gaara identity throughout.

For **Breakout Shukaku**, the visual read should be:

> **the seal has been forced far enough that Shukaku is being driven outward into physical manifestation.**

Do not use:
- Black Gold Naruto palette;
- generic red/black Kurama chakra cloak language;
- nine-tail imagery;
- friendly Shukaku expression;
- cooperative Magnet Release presentation by default;
- a simple recolour of existing Breakout Kurama.

## Future asset expectation

The exact Dark Gaara stage count and names before Breakout Shukaku are **not yet locked**.

Character Creation / Visuals should therefore queue:
- future Dark Gaara coercive-route Character Card representation(s), exact stage list pending Progression/Story/Registry closure;
- **Forced Manifestation / Breakout Shukaku** Character Card;
- matching Battle/UI portrait(s) where runtime needs them.
