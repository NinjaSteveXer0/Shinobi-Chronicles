# 3. Generic post-resolution decision-continuation classification

After any Battle/resolver leaves a participant defeated or controlled, runtime must classify that participant before presenting Kakashi's next action.

Possible classes:

## `CONTROLLED_DEFEATED`

Participant is physically under Kakashi's control / incapable of preventing the immediate disposition.

Eligible Story actions may include, where branch authority permits:

- deterministic **KILL**;
- secure custody / return to authority;
- existing authored disposition choice;
- leave participant and continue mission;
- another explicitly authored disposition.

A deterministic KILL remains governed by the existing deterministic-kill contract.

## `DEFEATED_BUT_NOT_CONTROLLED`

Participant lost the confrontation but retains enough agency / position / intervention uncertainty that Kakashi does not possess guaranteed disposition control.

Eligible lethal action, if authored, is:

- **ATTEMPT TO KILL — RESOLVER-DETERMINED**.

The resolver may return death, survival, interruption, escape or another legal result.

## `ESCAPED / UNAVAILABLE`

No immediate lethal/disposition action is presented.

## `DEAD`

No further kill/disposition decision exists. Death is already committed.

This classification is the bridge that allows the same Origin to produce:

- deterministic kills;
- failed lethal attempts;
- successful resolver-determined lethal outcomes;
- deliberate nonlethal custody;
- deliberate continuation without resolving every defeated actor.

Counts/ending state must come from committed receipts, never inferred presentation.
