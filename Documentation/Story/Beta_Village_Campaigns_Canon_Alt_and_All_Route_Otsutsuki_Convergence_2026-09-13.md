## 1. Purpose

Stephen has now fixed a post-Alpha / Beta campaign architecture for Shinobi Chronicles:

> **Every supported village receives its own storyline in Beta. Each village storyline has a Canon route and an Alt route. At the end of either completed village playthrough, the campaign enters a shared All-Route that brings the villages into an Ōtsutsuki-scale challenge.**

This document makes that architecture durable without prematurely authoring every village, every Mission, or every Ōtsutsuki encounter.

This is **future Beta authority** and must not displace the current primary priority:

> **Finish Shinobi Chronicles Alpha.**

Preserve throughout:

- village != country;
- village storyline != universal world history;
- Canon route != route-family morality axis;
- Alt route != evil route;
- All-Route != erasure of prior route history;
- convergence != retroactive normalization;
- village alliance != permanent political unity;
- Ōtsutsuki challenge != automatic PL/Skill/reward grant;
- Beta design closed != implemented != runtime validated != Golden GREEN.

# 2. Beta village-campaign architecture

## 2.1 Every supported playable village receives its own campaign

Beta should expand Shinobi Chronicles beyond Konoha-centric Main Story by authoring a dedicated campaign for each supported playable village.

The exact Beta village roster is **not closed by this document**.

Do not infer that every named country automatically contains one supported playable village, and do not equate World Map country anchors with village/capital authority.

When a village is added to the supported Beta campaign set, it must receive more than:

- a reskinned Konoha story;
- a single introductory Mission;
- a different map with identical political beats;
- one Kage cameo;
- a generic `foreign village` route.

Each village campaign should express that village's own:

- historical pressures;
- political institutions;
- local relationships;
- military/security assumptions;
- clan/family/social structure where relevant;
- geography and World opportunities;
- Jinchūriki/Tailed-Beast history where continuity-valid;
- neighbouring-country pressures;
- rivalries/alliances;
- hidden history;
- local route consequences;
- distinct protagonist opportunities.

Canon Research First remains binding before exact canon-derived village content is authored.

# 3. Every village receives Canon + Alt campaign realizations

Each supported Beta village campaign must support two top-level authored campaign realizations:

1. **Village Canon Route**;
2. **Village Alt Route**.

These are village-campaign structures, not replacements for the existing political/strategic route families such as Reform, Dominion, Rogue, Take the Throne/Leader, or Non-Conformance.

A Chronicle may carry route-family history inside either Canon or Alt village realization where causally legitimate.

## 3.1 Village Canon Route

The Canon Route preserves the selected village's recognisable historical/political identity while allowing Shinobi Chronicles Recorded History to diverge through player action.

`Canon` does **not** mean every Naruto/Boruto canon event must occur unchanged.

The correct model remains:

`CANON ANCHOR -> SC DIVERGENCE -> COMMITTED CONSEQUENCES`.

## 3.2 Village Alt Route

The Alt Route is a materially different authored campaign realization that remains anchored to the same village/characters/world but follows a deliberate alternate structural premise.

Alt must not mean:

- evil route;
- joke route;
- identical missions with different dialogue;
- protagonist gets arbitrary forbidden power;
- all village institutions automatically invert allegiance.

The Alt route should create a genuine second-playthrough campaign identity.

## 3.3 Canon and Alt both preserve Chronicle causality

Neither route is a fixed movie.

Within its authored structure, CE still consumes:

- actual relationships;
- Knowledge;
- team/origin history;
- world state;
- capability;
- political route evidence;
- prior choices;
- local participants' autonomous intent;
- legitimate system-owned outcomes.

`Canon/Alt route selected or realised != exact outcome predetermined`.

# 4. All-Route — shared post-village convergence

## 4.1 Binding definition

> **All-Route is a shared post-village campaign movement that becomes available after a supported village playthrough completes its Canon or Alt route and escalates the Chronicle into an Ōtsutsuki-scale world challenge involving the wider village system.**

This means every supported village playthrough has a route into the All-Route endgame.

The player does **not** need to abandon or overwrite the history of the village campaign in order to enter All-Route.

The All-Route should consume that playthrough's actual Recorded History.

Examples of facts that may materially change an All-Route realization include:

- which village the Chronicle began from;
- Canon vs Alt village history;
- current village leadership;
- allies/enemies;
- Kage relationships;
- Jinchūriki/host/beast state;
- surviving/dead/estranged teammates;
- foreign treaties;
- unresolved conflicts;
- hidden-area discoveries;
- rare capabilities;
- political route-family history;
- prior cooperation with other villages;
- betrayals or atrocities that other villages remember.

The common endgame threat does not erase those differences.

## 4.2 Convergence without normalization

All-Route is allowed to create a common world-scale crisis while preserving different causal arrivals.

Canonical shorthand:

> **Every village can reach the same world-scale threat without pretending every village lived the same history.**

Do not implement All-Route as:

`reset politics -> everyone is friends -> fight alien boss`.

Villages may cooperate because the threat requires it while still:

- distrusting each other;
- withholding information;
- bargaining over command;
- protecting their own people first;
- refusing specific joint actions;
- pursuing parallel plans;
- carrying unresolved wars/grievances into the operation.

Cooperation under existential pressure != permanent alliance.

# 5. Ōtsutsuki challenge — forward endgame role

## 5.1 Canon anchor

Current official Naruto/Boruto material establishes a safe baseline that Ōtsutsuki threats can operate above ordinary Hidden-Village politics:

- Kaguya Ōtsutsuki is tied to the ancient origin of chakra/shinobi history;
- Isshiki invaded alongside Kaguya and later pursued resurrection through a vessel;
- Momoshiki and Kinshiki trigger a Five-Kage-scale response;
- Ōtsutsuki/Karma material supports threats whose consequences exceed a single village's normal military dispute.

Shinobi Chronicles may diverge deliberately from exact Boruto continuity when the Beta All-Route is later authored.

## 5.2 Binding All-Route role

> **The All-Route culminates in an Ōtsutsuki challenge that requires the wider village world to confront a threat beyond ordinary village rivalry.**

The exact challenge may include Story, World, Combat and challenge/endgame content, but this document does not author exact enemies or mechanics.

The point is not simply `bigger PL number`.

The Ōtsutsuki challenge should test whether the world/history created by the village playthrough can function when:

- no single village can plausibly own the whole response;
- existing rivalries still matter;
- exceptional bloodlines/hosts/capabilities may become strategically important;
- inter-village trust has actual provenance;
- prior route choices affect who cooperates and how;
- the player's home-village history changes their authority and access inside the coalition/challenge.

## 5.3 System ownership

Writing owns:

- All-Route Story structure;
- the causal reason the world-scale crisis reaches every village;
- route/village-history callbacks;
- authored narrative introduction/escalation/conclusion.

World / Missions / Events owns:

- exact locations;
- world opportunities;
- travel/access/actionability;
- local/international event ecology.

Combat / Skills / Items / Weapons owns:

- exact Ōtsutsuki Battle callers/packages;
- combat-capability semantics;
- enemy mechanics;
- Skills/items/weapons effects.

PL / Registry / Rank owns:

- exact Registry identity/representation and Base PL authority;
- no direct hidden PL inflation merely because content is endgame.

Acquisition / Character Systems owns:

- rare-card / character obtainability;
- ownership commits;
- reward provenance.

Progression owns persistent development where separately authorised.

Story must not hard-code exact PL thresholds, drop tables, or ownership rewards.

# 7. Replayability principle

The purpose of separate village campaigns is not just content volume.

Each village should create a materially different route into the eventual All-Route.

Therefore a Sand-origin All-Route, Mist-origin All-Route, Cloud-origin All-Route, Stone-origin All-Route, Leaf-origin All-Route, or later smaller-village realization should not feel like the same prologue with a different home banner.

Differences may legitimately affect:

- who has protagonist trust;
- which Kage/leader gives access;
- who commands or refuses command;
- which Jinchūriki/host relationships exist;
- which villages arrive early/late;
- which historical evidence is known;
- which capabilities or hidden areas are accessible;
- which village bears prior grievances;
- which characters can be fielded/contacted;
- which endgame tactics are politically possible;
- which post-challenge settlement is plausible.

All-Route is shared architecture, not identical history.
