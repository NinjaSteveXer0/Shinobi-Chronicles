## 3. Hard system boundaries

### 3.1 Entity PL never transfers wholesale

Never:

`host PL + beast PL`

Never:

`summoner PL + summon PL`

The legitimate models are:

- source-owned Stat modifiers -> recompute Effective PL exactly once;
- exact resolver effects outside PL;
- exact Skill/action access;
- independently manifested Entity uses its own Battle PL ledger and action economy;
- dedicated Character representation may already embody the relationship/transformation in its own Base Stats/PL.

### 3.2 Dedicated representation anti-double-count

If a Character representation already embodies the relevant beast state in Base Stats/Base PL, do not apply the same hosted/relationship modifier package again.

Examples requiring this guard include current representations such as:

- `jinchuriki_sakura_chomei`;
- `jinchuriki_tobirama_shukaku`;
- `jinchuriki_shikamaru_yang`;
- `jinchuriki_shikamaru_yin`;
- `jinchuriki_naruto_v1`;
- `jinchuriki_naruto_v2`;
- `one_tailed_chakra_cloak_menma`;
- `kurama_resonance_himawari`.

**embodied representation != apply the source package again**

### 3.3 Access is not manifestation

Preserve:

**ownership/access != prepared != active != manifested != independently deployed**

A source can be known/owned/hosted without granting:

- a second turn;
- a second deployment slot;
- a second Battle PL ledger;
- passive Stats;
- every source-family Skill.

### 3.4 Tailed Beast is not ordinary Summon

Tailed Beast is an Entity family/representation classification. Exact lifecycle may be:

- hosted;
- voluntarily loaned;
- independently manifested;
- forced manifestation;
- dedicated Jinchūriki representation;
- transformation/partial cloak;
- occurrence-owned cooperation.

Do not force these through generic Summon-contract semantics.

List which dedicated Character forms already embody this source so the runtime cannot apply the relationship package twice.

## 9. Enhancement design rule for this tranche

Each source gets a **small, identity-specific package**, not a generic stat-stick template.

When an enhancement profile is legitimate, prefer:

1. **one primary identity-defining modifier or capability**;
2. **one secondary affinity/discipline/utility effect**;
3. **one exact signature relationship technique or resolver effect**.

A fourth component is allowed only when canon/SC representation genuinely requires it.

Avoid:

- nine beasts all receiving `+N Ninjutsu`;
- every Summon giving Crit;
- generic friendship multipliers;
- hidden PL multipliers;
- passive regeneration by default;
- unexplained affinity percentages;
- duplicated effects already embodied in a Character variant.

Exact numbers remain subject to balance/PL review where they change Effective Stats.
