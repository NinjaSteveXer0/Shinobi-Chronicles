# 4. KEEP lock

> **Sakon and Ukon's unnamed cellular-fusion kekkei genkai is KEEP for Shinobi Chronicles.**

Its SC identity should not primarily be a passive Stat stick.

The defining gameplay question is:

> **Who can this person safely share a body with, under what relationship/history/provenance, and what exact verbs have that pair learned to perform while fused?**

Preserve:

**Bloodline possession != universal fusion compatibility**  
**relationship != automatic Access**  
**fusion Access != full shared repertoire**  
**shared body != shared identity**  
**shared body != shared ownership**  
**fusion != additive PL**

---

# 5. Friendly / consensual bonded fusion — explicit Shinobi Chronicles divergence

Canon demonstrates Sakon/Ukon cohabitation and hostile attachment to another person's body. It does not establish a generic safe long-term consensual teammate-fusion system.

Shinobi Chronicles deliberately extends the canon anchor.

Canonical SC divergence direction:

`canon cellular fusion/separation`

→ `specific compatible living partner`

→ `mutual consent where friendly fusion is intended`

→ `shared training / relationship / Chronicle history`

→ `person-specific fusion Access`

→ `pair-specific developed expressions`

A high Relationship value alone must not manufacture compatibility or mastery.

Progression / Relationship authority may later require exact evidence such as:

- repeated shared Battles;
- mutual rescue/protection history;
- specific training occurrences;
- trusted bodily/chakra exposure;
- prior successful partial fusion;
- compatibility testing;
- explicit consent;
- recovery from a failed/unstable fusion;
- other exact pair-specific Chronicle evidence.

## 5.1 Different relationships should create different verbs

Two fusion-compatible pairs with the same Bloodline need not develop the same repertoire.

Possible future expression families include, but are not limited to:

- extra-limb Taijutsu/Bukijutsu assists;
- blind-side interception;
- pair-specific guard/counter timing;
- shared sensory posture;
- emergency internal carrying/extraction;
- infiltration through concealed co-occupancy;
- rapid fission/re-merge;
- pair-specific combination Skills based on demonstrated shared training;
- exact cooperative recovery/stabilisation expressions.

These are design families, not automatic Skills granted by this lock.

Canonical design principle:

> **Bloodline + exact partner + actual shared history can create a verb that neither the Bloodline nor the Relationship score grants in isolation.**

# 6. Shared-body Battle semantics

Friendly fusion creates a **shared physical position/body state**, not one new merged person.

At minimum preserve:

- each person keeps a stable persistent identity;
- each person's Bloodline/Skill/Equipment/Hosted Entity ownership remains separately addressed;
- fusion does not create a new Base Stats ledger by adding both participants together;
- fusion does not add both Base PL values together;
- temporary fusion does not mutate either participant's Base Stats/Base PL;
- one shared body does not automatically receive two full independent turns;
- fission does not grant a free initiative burst;
- merging does not duplicate Equipment or pouch contents;
- arbitrary teammate fusion does not refund a deployment/team slot merely because two deployed Characters occupy one physical location.

Exact action economy remains for later Combat closure.

A fused support participant may contribute only through exact authored assist/rider/combination actions rather than an automatic second full action stream.

---

# 7. Jinchūriki / Hosted Entity fusion lock

The Sakon/Ukon Bloodline acts on the participating bodily persons. A Tailed Beast / Hosted Entity does **not** become ordinary cellular material merely because its host fuses with another person.

If a Bloodline bearer fuses with a Jinchūriki / Hosted Entity host:

- the Hosted Entity remains attached to its original host relationship unless separate authority changes that relationship;
- the fusion partner does not acquire ownership of the Hosted Entity;
- the fusion partner does not automatically gain the host's Tailed-Beast Skills;
- the Hosted Entity does not automatically cooperate with the fusion partner;
- the host remains the legitimate host/controller relationship participant;
- hosted manifestation/transformation remains source-gated;
- shared body does not merge Hosted Entity identity with either human identity;
- Hosted Entity PL is not added into a new fused PL ledger.

Preserve:

**human fusion != Hosted Entity fusion**  
**shared body != shared host ownership**  
**co-location != cooperation**  
**cooperation != mastery**

# 8. Multi-host / multi-presence shared-body states are supported semantically

Existing CE authority already permits one Character to host multiple separately-addressed Hosted Entities and requires each to remain a distinct causal identity.

Relevant authority:

`Documentation/Coordination/Menma Multiple Hosted Entity and Echo Arc 1 Contract 2026-09-09.md`

Therefore a future fusion state may legitimately contain more than two causal participants when the exact underlying relationships already exist.

Example semantic case:

- Menma;
- Menma's Echo Hosted Entity;
- a Menma-hosted Kurama relationship where separately authorised;
- Naruto;
- a Naruto-hosted Kurama relationship where separately authorised.

If all of those are simultaneously active in one friendly shared-body fusion, there are **five distinct causal presences**, not one five-way merged Entity.

This does not automatically prove that every such combination is currently obtainable. It proves that the ontology/Combat design must not forbid the state merely because more than two causal identities share one physical position.

Canonical multi-presence rule:

> **shared physical body/position does not collapse persistent identity, hosted-entity relationship, ownership, Knowledge, cooperation, capability Access, PL ledger, or decision authority.**

Each source remains independently addressable.

# 9. Extreme cooperative host-state direction

A future exceptional Chronicle route may allow a bonded fusion pair to remain safely fused while one or both legitimate Jinchūriki participants enter an authored cooperative cloak/transformation state.

This is not a baseline Bloodline bonus.

Potential prerequisites may include:

- exact fusion compatibility;
- exact Hosted Entity cooperation;
- transformation compatibility;
- repeated survival/training history;
- consent among human participants;
- Hosted Entity willingness where the relevant hosted power requires cooperation;
- sufficient Competence/Mastery under later Progression authority.

Such a state may enable unique combination actions that cannot exist for an ordinary Bloodline bearer or ordinary Jinchūriki.

It still may not:

- add every participant's PL together;
- expose every participant's Skills to every other participant;
- transfer Tailed Beast ownership;
- create one new permanent fused person automatically;
- erase the possibility of disagreement/refusal among internal participants.

# 10. Loss-of-control interactions are intentionally supported

Naruto canon demonstrates that Nine-Tails power can erupt beyond calm host control, while later cooperation produces a very different controlled partnership state.

Shinobi Chronicles should preserve that distinction during fusion.

If a fused Jinchūriki loses control:

- fusion does not immunise the other participant;
- the second participant may become physically trapped inside the same destabilising host-state;
- the Hosted Entity remains its own causal source;
- exact fusion stability may deteriorate or become contested where later mechanics author that interaction;
- a partner cannot simply claim control of the host's Tailed Beast because they share the body.

## 10.1 Dual loss-of-control case

Stephen explicitly wants the system to support the possibility that **two fused Bloodline-bearing Jinchūriki independently lose control in the same Battle**.

This is KEEP as an extreme emergent interaction direction.

If both participants each have their own separately-authored Hosted Entity / Tailed-Beast relationship and both destabilise:

- resolve each loss-of-control source independently;
- do not automatically combine them into one super-Hosted Entity;
- do not automatically add their PL;
- do not assume the two Hosted Entities cooperate merely because their hosts are fused;
- do not assume either human remains sole uncontested controller;
- allow the shared-body state itself to become unstable/contested/catastrophic where exact future Combat mechanics author that consequence;
- preserve all observer/evidence/history as source-specific.

Canonical design direction:

> **simultaneous hosted destabilisation inside a fused body is a multi-source conflict state, not a free transformation upgrade.**

This is deliberately capable of producing extraordinarily dangerous emergent Battles.

# 11. Hostile fusion / cellular invasion — KEEP as advanced branch

Hostile fusion is a core part of why this Bloodline is worth retaining.

Canon anchor:

- Ukon can attach to Kiba;
- host self-injury also injures Ukon;
- databook/manga-backed Parasite Demon Demolition is an assassination technique that disassembles Ukon's body to cellular/protein scale, invades the victim, and destroys/corrodes the target internally;
- this exact assassination technique is associated with Curse Seal Level 2 in canon.

SC lock:

> **Bloodline possession alone does not grant unrestricted hostile cellular assassination.**

Hostile invasion must be an exact advanced expression with its own Access/cost/risk/provenance.

Potential runtime representation should prefer one source-owned invasion relationship/state rather than a pile of generic Conditions.

Critical canonical counter/risk to preserve:

> **damage to the invaded host can damage the invader.**

This creates legitimate self-harm-to-expel / ally-intervention / internal-counterplay possibilities where authored safely in Battle semantics.

## 11.1 Hostile invasion of a Jinchūriki is especially dangerous

A hostile invader entering a Jinchūriki does not gain ownership/control of the Hosted Entity.

Instead, the invader has placed itself inside a body containing another autonomous causal presence.

A hostile invasion occurring during:

- Tailed-Beast chakra eruption;
- host loss of control;
- cooperative transformation;
- internal seal conflict;
- another Hosted Entity manifestation;

may create extraordinary risk to the invader under exact future mechanics.

The Bloodline must not become a universal anti-Jinchūriki exploit merely because it attacks internally.

# 12. Echo Menma specific semantic note

`Echo Menma` is a representation of the persistent Menma person, while the Echo remains a distinct Hosted Entity.

Therefore any future case described conversationally as:

`Echo Menma + Naruto + Menma's Kurama + Naruto's Kurama`

must not accidentally count Echo Menma as only one causal presence if the Echo is actually present.

Where all relationships are active, the correct causal set is:

1. Menma;
2. Menma's Echo;
3. Menma's separately-authored Kurama Hosted Entity relationship;
4. Naruto;
5. Naruto's separately-authored Kurama Hosted Entity relationship.

This five-presence state is semantically legal **only where every individual possession/hosting/access/fusion predicate is independently satisfied**.

No automatic current-game availability is implied by this example.

# 13. Low-asset / low-status compatibility

This Bloodline remains compatible with the current Bloodline low-asset doctrine.

It should not require an icon for every partner/fusion outcome.

Prefer:

- one Bloodline family presentation;
- exact relationship/fusion records;
- one shared-body runtime relationship object;
- exact source-owned transient markers;
- ordinary Battle log/contextual feedback;
- bespoke player-facing Conditions only where players genuinely need to track persistent state.

Do not create `fused_1`, `fused_2`, `extra_arm`, `extra_leg`, `kurama_inside_fusion`, etc. as permanent status-icon spam.

# 15. Final lock

> **Shinobi Chronicles retains Sakon and Ukon's unnamed cellular-fusion kekkei genkai as a relationship-driven Bloodline. Its signature SC extension is person-specific consensual fusion whose repertoire develops from actual shared history. Fusion may coexist with separately-addressed Hosted Entities and may therefore create extreme multi-presence states—including independently destabilising Jinchūriki—without collapsing identities, ownership, Access or PL.
