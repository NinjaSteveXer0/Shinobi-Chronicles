# Shinobi Chronicles — Alpha Skill / Item Catalogue Source-Binding Boundary

**Date:** 2026-09-10  
**Owner:** Combat / Skills / Items / Weapons  
**Status:** **BOUNDARY CLOSED — EFFECT AUTHORSHIP VS SOURCE/GRANT AUTHORSHIP**

Combat's broad text-first catalogues define stable content identities and executable effects. They do not decide that an arbitrary Mission, training action, shop, mentor or discovery grants those rows.

Required division:

- **Combat / Skills / Items / Weapons:** stable Skill/Item/Weapon/Gear identity within its domain, exact Battle effect, compatibility/payload semantics, equipment modifiers, rarity classification.
- **World / Missions / Events / Rewards:** factual reward/source opportunity and mission/world context where relevant.
- **Progression / Development:** persistent learning/development/access state and qualifying evidence where a Skill requires development.
- **Acquisition / Inventory authority:** actual ownership/grant transaction where applicable.
- **Coding:** implementation/persistence/consumer wiring and Golden/regression.

A mission or training activity may reference an existing stable catalogue ID once its owner closes the legitimate source/grant seam. It must not create a mechanically divergent duplicate Skill definition solely because it is awarded from a different source.

Conversely, a catalogue row naming `mission_mentor_or_scroll`, `element_training`, `fuinjutsu_training` or another acquisition family does not itself create a mission, mentor, training activity, drop table or grant occurrence.

Preserve:

- effect definition != acquisition source;
- source eligibility != grant;
- grant != prepared palette;
- prepared != Battle-legal in every context;
- mission completion != Skill unlock automatically;
- training attempt != access automatically;
- catalogue rarity != reward probability;
- same Skill from different legitimate histories may preserve different acquisition provenance while sharing one executable definition.
