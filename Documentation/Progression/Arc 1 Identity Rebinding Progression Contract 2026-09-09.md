## 1. Purpose

This contract closes the minimum Alpha persistent-development authority for the Arc 1 Mission 3–6 False Identity / Identity Rebinding chain.

It consumes Writing’s machine-addressable factual occurrences and supplies the persistent development predicates later systems may read. It does not redesign Fūinjutsu generally, create a generic Technique-learning subsystem, grant hidden PL, or collapse representation into identity.

Canonical chain:

`committed factual Story evidence`

→ `occ_arc1_m6_identity_rebinding_seal_created`

→ persistent Identity Rebinding development/access

→ optional current body-inscribed Identity Rebinding state

→ `occ_arc1_m6_cipher_menma_history_established` where factually present

→ `cipher_menma` representation eligibility while that current seal state exists

→ later Recognition Substitution may consume the persistent capability predicate plus its own current system/state requirements.

Preserve:

**Knowledge ≠ Access ≠ Competence ≠ Power ≠ Mastery**  
**Mission completion ≠ Progression grant**  
**stable person ≠ representation**  
**representation visibility ≠ capability authority**  
**Progression ≠ PL**

## 4. Persistent Knowledge versus persistent capability

The following remain separable:

- observed recognition behaviour;
- retained reference material;
- calibration experience;
- Third Bell acceptance observation;
- Archive understanding of trusted identity propagation;
- Identity Rebinding capability Access;
- current body-inscribed seal state;
- Cipher Menma representation eligibility;
- Recognition Substitution action eligibility.

A Chronicle may contain some Knowledge/evidence without Access if the M6 creation occurrence never commits.

Once legitimate M6 creation commits, later loss of a current seal inscription, representation change, object loss, or presentation refresh does not erase the already-earned development record or its factual history.

Conversely, persistent Access does not guarantee that every target system can be fooled. Target compatibility and action resolution remain separate capability/runtime concerns.

## 5. Cipher Menma representation eligibility

`cipher_menma` is a representation of the same stable Menma person, not a separate historical person.

Progression authorises **current `cipher_menma` representation eligibility** only when all of the following are true:

1. the stable subject is Menma;
2. `occ_arc1_m6_cipher_menma_history_established` is committed for that Menma;
3. that occurrence references the factual supporting body-inscribed Identity Rebinding seal state;
4. the referenced seal state is currently present/active enough for the Chronicle-specific Cipher representation to remain truthful.

The representation predicate is therefore based on current factual seal state + committed history, never on `mission6Complete`, a UI selection, inventory presence, or ordinary Menma rank.

`genin_menma` remains the ordinary Genin Menma representation and does **not** imply the Chronicle-specific body-inscribed Identity Rebinding seal.

If the current body-inscribed state is later removed/suppressed/absent by legitimate authority:

- Menma remains the same stable person;
- the persistent Identity Rebinding development/access record remains earned;
- the historical `occ_arc1_m6_cipher_menma_history_established` occurrence remains true history;
- current `cipher_menma` representation eligibility may become false until a legitimate current state again supports it.

Preserve:

**history persists ≠ current representation must persist**  
**capability persists ≠ current inscription persists**

## 6. Recognition Substitution prerequisite compatibility

Later Combat action:

`arc1_m11_menma_recognition_substitution`

must not create earlier competence retroactively.

Progression supplies the following exact prerequisite predicate:

### Persistent capability predicate

`IdentityRebindingAccessSatisfied(actor)` is true only when:

- actor resolves to the exact stable Menma participant who earned the development record;
- that participant has one legitimate persistent `false_identity_seals.identity_rebinding_seal` development record sourced from committed `occ_arc1_m6_identity_rebinding_seal_created`;
- the record has Access = GRANTED and at least INITIAL OPERATIONAL COMPETENCE;
- the record has not been explicitly invalidated by a future authority that specifically revokes learned capability itself. Mere representation/seal-state loss does not revoke it.

This predicate is **necessary but not sufficient** for Recognition Substitution to succeed.

Combat / Skills / target-system authority still owns exact current compatibility and resolution, including whether the target reads a form of identity information the capability can affect, whether the required current seal/system state exists, and whether the attempt succeeds or is resisted/countered.

Progression does not require `cipher_menma` to be the currently displayed representation merely to prove that the learned capability exists. If the action itself requires an active body-inscribed state, that is a separate current-state prerequisite supplied by Skills/Combat/Story authority rather than inferred from the portrait/representation.

Preserve:

**Access predicate ≠ automatic action success**  
**Cipher representation ≠ Recognition Substitution permission by itself**  
**Recognition Substitution ≠ retroactive Technique learning**

## 7. Save/load, retry and idempotence

One committed factual source may mint at most one persistent Identity Rebinding development grant for the exact subject.

Semantic dedupe identity is:

`(stableSubject, false_identity_seals.identity_rebinding_seal, occ_arc1_m6_identity_rebinding_seal_created)`.

Rules:

- reloading after commit restores the same development record;
- retrying the same factual occurrence does not mint another record;
- replaying presentation does not create Access again;
- re-reading earlier M3–5 evidence does not duplicate Access;
- a failed/aborted/pre-commit M6 creation attempt grants nothing;
- `occ_arc1_m6_cipher_menma_history_established` is separately idempotent and must not duplicate representation history;
- save/load must not silently invent supporting occurrences that were absent from the actual Chronicle;
- later current-state removal may change representation eligibility without deleting development history.
